개발 과정 기록입니다. 정산 금액, 연락처, 개인적인 사정/감정 표현, 팀원 간
사적인 대화는 전부 제외했고, 엔지니어링 의사결정과 진행 상황만 날짜순으로
정리했습니다.

## 2026년 8월 19일 (수)
- 기존 프로젝트 구조 정리: 장갑(Flex Sensor 5개 + MPU-6050 + ESP32) → BLE →
  RN4020 → Arduino Nano → Max Pfeiffer의 오픈소스 EMS 툴킷 "LetYourBodyMove"
  → 상용 EMS/TENS → 전극 패드로 이어지는 구조. (그동안 "openEMSstim"이라 부르던
  것이 실은 LetYourBodyMove 보드였음을 이 시점에 정정.)
- 전자상가에서 팀 전체가 모여 PCB 보드·배선 납땜 진행. 보드 납땜은 완료, 전선
  납땜은 업체에 추가 의뢰.
- 양쪽 글러브의 플렉서블 센서 위치를 서로 맞추는 작업 수행.
- ESP32 기반 초기 펌웨어 초안 작성: 글러브A(센서1~5=목표값)·글러브B(센서6~10=
  실제값)의 굽힘률 오차를 계산해 자극 세기를 조절하는 폐루프 제어 코드
  (EMS/FES 파형 자체는 생성하지 않고 Serial 출력까지만 구현).
- 검증 절차 수립: ①육안검사 → ②멀티미터로 쇼트 확인 → ③Nano 자체
  Blink/Serial 테스트. 9V 배터리 입력은 Nano의 5V 핀이 아니라 VIN/레귤레이터
  경로로 들어가야 한다는 점을 확인 필요 사항으로 기록.
- 2채널 중 1채널만 정상 동작, 2채널 미동작 문제 최초 발견 (모든 게이트를 열어도,
  2채널 게이트만 여는 정정 코드로도 동작 안 함 → 배선/기판 자체 문제 가능성).

## 2026년 8월 23일 (일) — ★ 플렉스 센서 → 카메라(MediaPipe) 방식 전환 ★
- 플렉스 센서 글러브를 구부려도 값이 안 나오는 문제를 조사하던 중, 고무 커버를
  뜯어 확인해보니 납땜이 금속 접점이 아닌 플라스틱 위에 되어 있고 전선이 내부
  여러 곳에서 끊어져 있는 것을 발견 (멀티미터로 저항 측정 시 굽혀도 저항 변화
  없음 — 최소 2개 이상 센서 완전 단선).
- 예선 제출 기한 내에 플렉스 센서를 재조달/수리하는 것이 현실적으로 불가능하다는
  결론에 도달.
- 한 팀원이 "지금 컴퓨터로 해보는 방법"이라며 카메라 기반 손 인식 방식을
  팀에 제안 (오후 2:25경). 스스로 "임시방편"이라 표현하며 다른 대안이 있으면
  계속 제시해달라고 요청.
- 같은 날 저녁, 카메라 기반 버전이 이미 상당 부분 동작함을 확인 ("일단 카메라로
  얼추 완성함, 2채널만 되면 이대로 가도 될듯").
- 밤 11시경, 그 팀원이 새 아키텍처를 정리해 공유: "AI 비전 피드백 기반 폐루프
  EMS 손동작 제어" — MediaPipe로 왼손 목표 동작을 측정하고 오른손 EMS로 실제
  자극을 주어 오차 기반 자동 보정하는 폐루프 구조. 이 시점까지 이미 완료된 것:
  양손 인식·굽힘% 계산, 캘리브레이션, 자연어 명령 처리(규칙 기반 + Gemini API),
  Arduino(OpenEMSstim 패치) ↔ PC 시리얼 프로토콜, 실제 팔 자극 테스트, 비례
  폐루프 제어(±5% 도달 시 자극 차단), 각종 안전장치, 개인화 캘리브레이션(자극값
  20/40/60/80 순차 테스트로 개인별 반응곡선 생성 — 지도교수 제안 반영).
- 참고: 하드웨어(EMS 자극, Arduino/OpenEMSstim, PCB)는 그대로 유지되고, 바뀐
  것은 "목표 동작을 측정하는 방식"이었다 (플렉스 센서 글러브 → 카메라 기반
  손 관절 인식).
- 같은 날, 지도교수 피드백을 통해 여러 후보 주제 중 "개인별 근육 반응 학습
  기반 EMS 개인화" 방향이 학부 프로젝트 범위로 적합하다는 의견을 받아, 이후
  주제를 구체화하는 근거가 됨.

## 2026년 8월 28일 (금) — 예선 제출
- 개발 세션 전체를 시간순으로 정리한 개발기록 보고서 작성. 이 시점까지의
  핵심 아키텍처: 카메라 한 대로 왼손(목표, SOURCE)·오른손(측정, ACTUAL)을
  동시에 MediaPipe HandLandmarker(21랜드마크, 2손 추적)로 인식 → 목표-실제
  오차를 비례(P) 제어기에 넣어 채널1(구부림)/채널2(폄) 세기 산출 → Web Serial
  API로 아두이노 전송 → AD5252 디지털 포텐셔미터로 세기 조절 → 외부 EMS/TENS가
  실제 자극 발생.
- 이 시점까지 발견·수정된 대표 버그: 채널1/채널2 핀 배선이 실제와 반대로 되어
  있던 버그, `EMSChannel::deactivate()` 이후 `check()`가 호출되지 않아 릴레이가
  완전히 꺼지지 않던 버그, 실시간 왼손 연동 값이 UI 정리 과정에서 계산 로직까지
  삭제되어 미갱신되던 버그, 음성인식 변수 선언 순서 문제(TDZ) 사전 발견.
- 제어 방식을 "오차 시 전류 차단 후 자연 이완 대기"에서 "채널1(구부림)/채널2
  (폄)이 오차 방향에 따라 자동 라우팅"되는 폐루프 방식으로 재설계.
- "행동 보조 모드"(사전 정의된 동작 버튼 + 실시간 왼손 연동) 신설. 목표 도달
  판정을 펄스형 → 연속 출력형으로 바꿔 반응속도 약 2.5배 개선.
- 거울/행동보조/개인화(수동 램프업) 3모드 체제 확립. "켜자마자 꺼짐" 버그의
  원인 3가지(전체 실험 타이머 초과, 연속 자극시간 제한 초과, 화면에 안 보이던
  안전정지 상태)를 순서대로 발견해 모두 해결.
- 행동 시나리오 구체화: "수저 들기 보조"(채널1 유지 → 채널2 순차 램프업),
  "이두운동"(채널2가 상승-유지-하강-휴식 반복).
- Web Speech API 기반 음성 명령("수저들기보조", "이두운동") 추가.
- 다층 안전 설계 확정: 최대 세기 기본값 0(직접 설정 필요), 연속 자극시간 제한,
  전체 실험 타이머, 두 채널 동시 활성 구조적 방지, SPACE/ESC/화면버튼/탭
  백그라운드 전환 시 비상정지.
- 밤샘 작업으로 발표 음성 녹음, 시연 영상 편집, 발표 대본·결과보고서(hwp)
  최종 검토. 보고서 표현을 일반 독자가 이해하기 쉽게 다듬음("MediaPipe" 풀어
  쓰기, "굴곡"→"굽힘"). 제출 명의상 팀장을 정함.

## 참고: 플렉스 센서 → MediaPipe 전환 경위 요약

초기 설계는 양손에 플렉스 센서 장갑(ESP32 기반)을 착용해 굽힘값을 직접
측정하는 방식이었습니다. 2026년 8월 23일, 장갑을 분해 점검하는 과정에서 센서
배선이 다수 단선된 것을 발견했고, 예선 제출 기한 내 수리·재조달이 불가능하다고
판단했습니다. 이때 한 팀원이 카메라(MediaPipe)로 손 모양을 인식하는 방식을
"지금 컴퓨터로 해보는 방법"이라는 임시방편으로 제안했고, 같은 날 안에 상당
부분 동작하는 프로토타입까지 만들어졌습니다. 이후 이 방식이 하드웨어 고장
위험이 없고 비용도 더 저렴하다는 장점이 확인되면서, 임시방편이 아니라 최종
아키텍처로 채택되어 지금의 웹캠 기반 시스템으로 이어졌습니다. (EMS 자극
하드웨어 자체는 그대로이고, 바뀐 것은 "목표 동작을 무엇으로 측정하는가"입니다.)
